Authentication

Signing up, verifying the email address, and managing sessions.

Start signing up a new account

Registers a pending sign-up attempt for the given email and password, and mails a 6-digit verification code to that address. No account is created and no authentication token is issued yet; the caller must pass the returned ticket and the mailed code to POST /signup/verify-email to finish. The email is canonicalized (lowercased) before storage, so uniqueness is case-insensitive. Returns 409 if the email is already registered, and 429 if the address has already been mailed 3 codes within the last hour. A 202 does not guarantee the email was delivered; the caller recovers through POST /signup/resend-verification.

Finish signing up by verifying the email address

Verifies the address behind the ticket returned by POST /signup against the code mailed to it. On success the pending attempt is promoted to a real account and an authentication token is issued, so the caller does not need to sign in afterwards. Returns 401 while the code is wrong and guesses remain, and 404 once no live attempt matches the ticket — which covers an unknown ticket, an expired one, and one whose guesses are used up alike. The attempt expires 10 minutes after the code was mailed, and the 6th wrong code kills it permanently, so even the correct code no longer verifies afterwards and the caller has to start over with POST /signup.

Mail another verification code

Mails a new verification code to the address behind the given ticket, so the caller does not have to hold the password a second time. This starts a fresh attempt rather than reusing the old one, so the response carries a new ticket that replaces the one the caller holds, the code from the earlier email no longer verifies, and the guess count starts over. Requires a live attempt for the given ticket, and is subject to the same limit of 3 codes per address per hour as POST /signup.

Sign in to an existing account

Authenticates with email and password and issues a new authentication token. A new token is issued per call, so signing in from multiple devices yields multiple concurrent sessions. Returns the same generic 401 whether the email is unregistered or the password is wrong.

Sign out of the current session

Revokes the bearer token in the Authorization header. The user's other tokens (e.g. from other devices) remain valid. This operation always returns 200 regardless of whether the token is present, already invalid, or malformed.

Save an item to the reading list

Saves an item to the reading list, either a web clip (via url), a feed entry (via feed_entry_id), or a web clip (via web_clip_id). Exactly one of the three must be specified. When saving a web clip, a placeholder item is appended immediately, and its content is fetched and filled in asynchronously afterwards; in this case a 201 response only means the placeholder was appended successfully — the clip fetch may still fail behind the scenes. An optional title may be supplied alongside url (e.g. the page title shared by the browser) to give the placeholder a meaningful label until the fetch fills in the real one.

Request Body schema: application/json

The item to save. Specify exactly one of url, feed_entry_id, or web_clip_id.

One of
url
required
string <uri>

The URL of the web clip to save.

title
string

Optional placeholder title (e.g. the page title shared by the browser). Shown until the clip is fetched; a successful fetch replaces it with the extracted title.
